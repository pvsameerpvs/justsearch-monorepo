## ⚠️ Architecture Clarification (CRITICAL)

**What this project actually uses:**
> **Shared-Schema Multi-Tenancy with `restaurantId` Foreign Keys**

All tenant data lives in the same database schema. Every table has a `restaurant_id` column that acts as the tenant boundary. This is simpler than schema-per-tenant and is the recommended approach for Supabase.

**Why not true schema-per-tenant?**
- Drizzle ORM migrations are designed for static schemas
- Dynamic schema creation requires raw SQL DDL execution
- Schema-per-tenant makes joins across tenants impossible
- Shared-schema with proper `restaurantId` indexing performs equally well

**How tenant isolation works:**
1. `tenant.middleware.ts` resolves subdomain → `public.restaurants` lookup
2. `req.tenant.id` = the restaurant's UUID
3. Every query includes `WHERE restaurant_id = req.tenant.id`
4. No cross-tenant data leakage (enforced at application layer)

## 1. Auth Architecture (Final)

| Portal | Method | Credential Source | Storage |
|---|---|---|---|
| **customer-frontend** | Name + Mobile + OTP | Self-signup | Per-tenant `users` table (filtered by `restaurantId`) |
| **justsearch-admin** | Username + Password | Manual creation | `public.super_admins` table |
| **restaurant-dashboard** | Username + Password | Created by justsearch-admin during onboarding | Per-tenant `staff` table (filtered by `restaurantId`) |
| **delivery-portal** | Username + Password | Created by restaurant-dashboard when adding rider | Per-tenant `delivery_agents` table (filtered by `restaurantId`) |

**Password Hashing:** `bcrypt` with cost factor 12 (industry standard).
**Customer OTP:** Database-backed (`otp_requests` table with `restaurantId`, 5-min TTL, max 5 attempts).
**Session Tokens:** JWT (signed with `JWT_SECRET`, 24h expiry, refreshed via cookie).

## 3. Drizzle Client Architecture (Actual Implementation)

```typescript
// src/db/index.ts
import { drizzle } from 'drizzle-orm/postgres-js';
import postgres from 'postgres';
import * as schema from './schema';

const connectionString = process.env.DATABASE_URL;

if (!connectionString) {
  throw new Error('DATABASE_URL environment variable is required');
}

// Single postgres pool
export const client = postgres(connectionString, {
  max: 10,
  idle_timeout: 20,
  connect_timeout: 10,
});

// Single Drizzle client with all schemas loaded
export const db = drizzle(client, { schema });

export type Database = typeof db;
```

**Important:** We use ONE Drizzle client, not multiple schema-specific clients. Tenant filtering is done via `WHERE restaurant_id = ?` in every query.

## 4. Tenant Resolution Middleware (Actual Implementation)

```typescript
// src/middleware/tenant.middleware.ts
export async function tenantMiddleware(req, res, next) {
  const host = req.headers.host || '';
  const baseDomain = process.env.NEXT_PUBLIC_BASE_DOMAIN || 'mydomain.com';

  // Extract subdomain from host
  let subdomain = '';
  if (host.endsWith(`.${baseDomain}`)) {
    subdomain = host.replace(`.${baseDomain}`, '').split('.').pop() || '';
  } else if (host.endsWith('.localhost')) {
    subdomain = host.replace('.localhost', '').split('.').pop() || '';
  }

  if (!subdomain) return next(); // No tenant context (super-admin or local)

  // Lookup restaurant in public.restaurants
  const [restaurant] = await db
    .select()
    .from(restaurants)
    .where(eq(restaurants.subdomain, subdomain))
    .limit(1);

  if (!restaurant) return res.status(404).json({ error: 'Restaurant not found' });
  if (restaurant.status !== 'active') return res.status(403).json({ error: 'Restaurant not active' });

  req.tenant = {
    id: restaurant.id,
    slug: restaurant.slug,
    subdomain: restaurant.subdomain,
    schemaName: restaurant.schemaName,  // Kept for future schema migration if needed
    status: restaurant.status,
  };

  next();
}
```

## 5. Every Query Must Filter by `restaurantId`

**This is the golden rule.** Any agent adding new queries must follow this pattern:

```typescript
// ✅ CORRECT: Always filter by restaurantId
const items = await db
  .select()
  .from(menuItems)
  .where(
    and(
      eq(menuItems.restaurantId, req.tenant.id),  // ← REQUIRED
      eq(menuItems.isAvailable, true)
    )
  );

// ❌ WRONG: Missing restaurantId filter
const items = await db
  .select()
  .from(menuItems)
  .where(eq(menuItems.isAvailable, true));  // Cross-tenant data leak!
```

**Tables that MUST have `restaurantId` filter:**
- users, staff, delivery_agents, restaurant_tables
- menus, menu_categories, menu_items, promo_codes
- orders, order_items, payments
- table_sessions, game_sessions, loyalty_points
- audit_logs, otp_requests, delivery_assignments, restaurant_users

**Tables that do NOT need `restaurantId` filter (shared/platform):**
- restaurants (the registry itself)
- games, advertisements, restaurant_games
- super_admins

## 6. Auth Middleware

```typescript
// src/middleware/auth.middleware.ts
export function authMiddleware(req, res, next) {
  const token = req.cookies?.token || req.headers.authorization?.replace('Bearer ', '');
  if (!token) return res.status(401).json({ error: 'Authentication required' });

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET!) as AuthContext;
    req.auth = decoded;  // { userId, role, restaurantId, type }
    next();
  } catch {
    return res.status(401).json({ error: 'Invalid or expired token' });
  }
}

export function requireRole(...roles: string[]) {
  return (req, res, next) => {
    if (!req.auth) return res.status(401).json({ error: 'Authentication required' });
    if (!roles.includes(req.auth.role)) return res.status(403).json({ error: 'Insufficient permissions' });
    next();
  };
}
```

## 16. Common Pitfalls to Avoid

1. **Forgetting `restaurantId` in WHERE clauses** — This is the most critical bug. Always verify with `grep "restaurantId"` on new query files.

2. **Using mock data in API responses** — The seed script provides real data. Remove all mock fallbacks once the DB is connected.

3. **Not running `db:push` before `db:seed`** — The seed script will fail if tables don't exist.

4. **JWT_SECRET too short** — Must be at least 32 characters. Use `openssl rand -hex 32` to generate.

5. **Confusing `restaurant_users` with `users`** — `users` = customers who sign up via OTP. `restaurant_users` = staff role mapping. `staff` = actual staff credentials.

6. **Forgetting `req.tenant` check** — All tenant-scoped routes must check `if (!req.tenant)` before querying.
